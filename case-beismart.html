BeiSmart KE

// The problem

Ten tabs, and no way to tell a real deal

Comparing prices across Kenyan online stores means opening a tab per store. The listings are noisy, with accessories, "free gift" bundles and inflated discounts mixed in. And a single look at today's price can't tell a real deal from a price that was raised just before a "sale".

// How it works

From one search to a price history

One search, every store

A search runs across all the stores at once and groups the same product, so its prices sit side by side. Filters cover price (with a histogram of the results), store and condition.

If a store fails, the rest of the results still load, and each store reports what happened: ok, empty, blocked, layout changed or timed out.

Every offer and its price history

A product page lists every offer for it, cheapest first, with a chart of how its price has moved. Every price change is recorded, so the history grows each day. Tracking began on 3 October 2026.

Amazon prices leave out delivery and import fees, so they're labelled as international and never count as a price drop.

Built for a phone too

On a phone the filters open as a bottom sheet, and the button shows how many results are left before you apply them.

The app works with a keyboard alone ("/" jumps to search, Esc closes the filters), has light and dark themes, and passed an automated accessibility audit (axe-core) on every screen with no problems.

A watchlist and price alerts

Products can be saved to a watchlist in the browser, which shows how each price has changed since it was saved.

In the full app you can also set a target price and get an email when a product drops to it. Alerts aren't in the read-only demo.

// The hard part

Getting honest data

Drawing the pages was the easy part. The work was in getting prices that can be trusted.

01

Stores that fight back

Four of the seven stores only work in a real browser. Jumia sits behind Cloudflare and lets only real Chrome through, Amazon sometimes shows a bot check, and Hotpoint's class names change on every deploy, so the scraper matches only their stable parts.

02

Matching products

Rules, not AI: each title is reduced to brand, model, size or storage, and new or refurbished. Listings merge only when all four are known and equal, because pricing two different TVs as one is worse than missing a match.

03

Hiding junk

Accessories and listings that are far too cheap to be real are hidden, each with a visible reason. The rules were tuned on real listings: words like "bag" were dropped because they hid real laptops sold with one.

// Status

Where it stands

Daily refresh19 searches, about 1,500 listings, in about 6 minutes
Matched83 products found at two or more stores (as of 5 Oct 2026)
Tests317 automated tests, all offline
DemoA static export of the same data, published after each daily check

Scraping needs real Chrome and a home connection, since stores would likely block a server's address. So the full app runs on my PC and refreshes on a schedule, and the public demo is a static snapshot on GitHub Pages. The site reads either the live API or the snapshot through one small data layer, so every screen works in both. Nobody uses it yet, and about 44% of products still can't be pinned to a brand and model, so they're shown on their own.

The first version was my final-year project, a Flask app with a Figma prototype and Draw.io system diagrams. In 2026 I rebuilt it from scratch.
